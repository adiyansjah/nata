## 1. Goal

Full external sort and bounded TopN (`ORDER BY ... LIMIT n [OFFSET m]`) for existing single-source scan/filter/project and grouped/HAVING queries, through `nata sql` and `nata serve`. Build the first new operator on a small physical pipeline graph, using [ADR 0016](../decisions/0016-pipeline-step-protocol.md), the existing CPU/Tokio services and [ADR 0009](../decisions/0009-query-memory-manager.md) grants. No runtime replacement.

```sql
SELECT l_orderkey, l_linenumber, l_extendedprice FROM 'lineitem.parquet'
ORDER BY l_extendedprice DESC NULLS LAST, l_orderkey ASC, l_linenumber ASC;

SELECT l_orderkey, l_linenumber, l_shipdate FROM 'lineitem.parquet'
ORDER BY l_shipdate ASC NULLS FIRST, l_orderkey DESC, l_linenumber ASC
LIMIT 100 OFFSET 20;

SELECT l_returnflag, l_linestatus, sum(l_quantity) AS qty FROM 'lineitem.parquet'
GROUP BY l_returnflag, l_linestatus ORDER BY l_returnflag, l_linestatus;
```

### SQL contract proposed for acceptance

[dialect](../dialect.md) and [supported SQL](../supported-sql.md) currently reject ordinary `ORDER BY`; metadata browsing's special shapes do not establish general sort semantics. Inherited comparison rules are binding; the new syntax/default/tie/evaluation rules below need the parent's acceptance and implementation-time dialect/ADR 0007 updates.

- Lexicographic multi-key ordering, each key independently `ASC` (default) or `DESC`, with explicit `NULLS FIRST`/`NULLS LAST`. Proposed omitted NULL placement: **LAST for both directions**, matching default DuckDB, independent of direction. NULL is handled before comparing non-NULL values; DESC reverses only their comparison. No locale collation.
- Keys are existing typed scalar expressions over source columns, or group keys/aggregate expressions after HAVING; allow a unique SELECT output alias as a whole ORDER BY key. Ambiguous output aliases are bind errors; a unique output alias takes precedence over an identically named source column. Aliases inside key expressions do not resolve. Keep hidden sort keys until the final projection. Ordinals and ORDER BY ALL remain unsupported.
- Signed TINYINT/SMALLINT/INTEGER/BIGINT compare without subtraction overflow; DECIMAL through precision 38 compares exactly, never by DOUBLE conversion. A bound key has one type/scale; expression coercion remains the dialect's strict rule. REAL/DOUBLE obey SQL comparison: all NaNs tie and exceed +infinity; `-0.0` and `+0.0` tie. Do not use raw float `total_cmp` without canonical comparison semantics. Preserve original payload values, including zero signs. Text compares UTF-8 bytes, dictionary values rather than dictionary IDs; dates compare signed Date32 days, including the documented column domain, not display strings. BOOLEAN orders FALSE before TRUE. No new type/cast support.
- **Stable ties:** preserve logical input sequence among rows equal on every explicit key, in full sort, TopN and every merge pass. Carry a checked internal sequence discriminator through runs and candidate eviction; it is not a SQL key or output column. For ordered Parquet input this is file/row-group/row order, assigned before parallel run generation, not worker completion order. For grouped input (or an explicitly unordered source) input order is unspecified: stability does **not** define ties across executions, task counts or plans. Users needing defined order and LIMIT membership must add a unique key. DuckDB tie order is not an oracle. Internal sequence overflow fails before wraparound.
- LIMIT/OFFSET retain non-negative integer-literal validation and existing unsupported forms. Compute `k=n+m` with checked arithmetic; overflow is a positioned bind error. Return at most n rows after discarding m from the sorted stream; n=0, m beyond input, empty input and n beyond input are explicit cases. No WITH TIES.
- Proposed ordered-query evaluation: WHERE, aggregate merge/checks and HAVING when present, then sort-key and selected output-expression evaluation for **all surviving rows**, then sort/TopN, OFFSET/LIMIT. LIMIT, including zero, cannot hide errors in these operations. This explicitly extends the scan-only projection/LIMIT rule in dialect §9b; do not silently alter unordered queries or aggregate strictness. TopN cannot stop reading arbitrary unordered input after k rows. Early-exit means stopping merge/output after k rows, closing remaining runs and cancelling unneeded work, while preserving already admitted output. Disconnect/cancel/deadline may interrupt every phase.

### Spill and pipeline delivery

Generate charged sorted runs at budget pressure/batch boundaries, including encoding keys, index/sort scratch and payload copies. Submit bounded local disk jobs; CPU steps return Blocked with sticky completion, never wait for disk or grants. Seal a run before publishing it. A bounded k-way merge (priority queue of run heads) emits charged output batches; when runs exceed admitted fan-in, perform intermediate merge passes. Derive fan-in from available grants and descriptor headroom (input readers plus output writer); at least two input heads and progress/output workspace must fit or return a clear resource-limit error. Charge simultaneous parent/child files until the child seals and parents close. Charge run descriptors too; keep their publication/manifest bounded rather than building an unbounded task/run vector. Oversize records fail clearly; no spike-style “sort anyway without a grant”. TopN keeps only charged k candidates plus bounded scratch across tasks, not k per worker outside B; on insufficient grant, transition to the same spillable run/merge path without losing candidates or tie identity.

Reuse [ADR 0010's accepted spill validation](../decisions/0010-hash-aggregation.md#amendments): Arrow IPC runs have a trusted query-derived typed schema (keys, payload and tie discriminator), bounded envelope and **interior** validation before Arrow allocation/decode. Cap metadata/body/rows/messages, verify nodes/buffers/ranges, string offsets and dictionary indices; no compression or dictionary deltas. Check schema/version, truncation, checksums and run monotonicity across frames; a checksum alone is insufficient. Sort-run schema needs an explicit ADR 0010 format amendment and damage tests; hash partition membership/hash/fan-out rules do not apply to runs. Preserve current payload/array caps, or stop for a separately versioned decision. Spill is private temporary state, never durable exchange/retry state.

Shape operator-neutral modules for grants/registry/quotas/byte credits/bounded handles/framing/completions so [card 0008 W-B](0008-engine-performance.md) can reuse them. **Sort runs and hash partitions keep separate policies**; no forced common partition abstraction. Reuse existing modules, no new spill crate now. Header reads run on the disk worker; encode/preflight/decode run in finite admitted CPU steps.

The graph records source → transforms → sort/TopN sink and its dependent ordered merge source → OFFSET/LIMIT/output, including aggregate → sort dependencies and required order. Sort is the last breaker; parallel upstream work cannot reorder the serial ordered result stream. Build a generic finite driver with Yield/Blocked/Done, continuation-owned batches/grants, bounded lazy task publication, dependency release after successful combines/finalize exactly once, sticky wakes and one runner per task. Finalization and merge are resumable work, not long coordinator callbacks. Source finish/close runs once on success, early finish, error and cancel; retain `stop_depth`, ordered scan/lowest-error promises and exchange close behavior. Implement the sort-consumed lifecycle now; reserve ADR 0001 A1 transform-finish and multi-producer hooks for first consumers in slices 7–9, with small protocol fixtures now, not new SQL features.

Use [ADR 0017](../decisions/0017-query-owner.md)'s agreed query handle seam for identity, cancel/deadline/stats and charge transfer; retain conservative existing pool subtraction. Full remote-owner integration stays in Track B/slices 11–12. An unavailable seam is a parent coordination blocker, not permission to create an independent sort budget.

## 3. Decision rules (fixed before measuring)

1. Accept the new SQL rules in §1 (NULL default, stable input ties, alias resolution and ordered expression/error scope), and ADR 0016 plus the needed ADR 0017 seam before implementation. Amend accepted ADRs by dated amendment only; write a sort-specific ADR if the parent needs a distinct decision record. Existing comparison/IPC/grant rules are not open choices.
2. Any correctness, lifecycle, fuzz/model or resource failure blocks **functionally complete**. A bounded-model timeout is NOT RUN/unresolved; INVALID mutants are not catches. No budget/default/threshold change, unordered output shortcut or decimal float fallback earns a pass. Small declared forced-spill fixtures must complete; clearly failing below minimum is not their substitute.
3. Reuse locked Arrow row encoding/sort/take primitives with strict adapters, std heap and existing spill modules first. If row encoding disagrees with the independent SQL comparator (notably NaN/zero), use a checked canonical-key adapter preserving payload; if that cannot be bounded, stop for a scoped alternative. Custom kernels/replacement codec require an ADR 0003 bake-off: ≥5% top self-time opportunity and ≥1.5x component gain on both CPUs, all semantics/bounds passing; until batched evidence, keep reuse. No scheduler rewrite based on historical spill latency.
4. TopN must equal stable full-sort-then-slice for every tested k/budget/thread count. Choose heap candidates with spill fallback as the initial bounded implementation; a faster selection algorithm is later measured work. A serial ordered final merge is accepted (ADR 0001 A1); no unjustified parallel-merge target.
5. Local smoke ≥2x flags investigation, not a performance pass/fail certification. Proposed T8 and scalability values remain deferred until the batched reference freezes them; preserve misses and unresolved cells, no retrospective thresholds. Functional completion is not closure.

**Dependency rule:** existing workspace crates and crates already in `Cargo.lock` may become direct dependencies at their locked versions (including Arrow components already selected by the ADRs), with `cargo deny` passing and unsafe inventory recorded. No new dependency is selected by this card. A crate absent from the lockfile is an open parent decision: report alternatives, direct/transitive package count, build/binary weight, unsafe code, licence/advisories and maintenance cost before adding it. Do not stop solely because a locked crate becomes direct.

**Not in scope:** joins/windows/set operations/CTEs, DISTINCT/WITH TIES, ORDER BY ALL/ordinals, collations, new types or coercions, distributed sort/exchange durability/retries, remote-owner certification, custom runtime/JIT/SIMD/allocator, spill compression/new codec/new crate, broad aggregate migration, admission/default changes, paid routine performance runs or claims that 0008's targets are met.

**Stop and report:** briefs name editable paths, check commands, one-child-turn time box (about 45 minutes), permitted reruns and defaults. Stop before an unlisted change/dependency, extra rerun, time-box overrun, changed threshold/default, protocol incompatibility or unsatisfied prerequisite; give evidence and the smallest proposed follow-up. No cloud action is authorized by this card. Out-of-scope findings remain proposals. Reports give rule as written, numbers (or NOT RUN/deferred), rule-derived verdict and reproduce command.
