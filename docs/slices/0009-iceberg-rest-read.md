## 1. Goal

Register a REST-backed Iceberg table in Nata's existing startup catalog configuration and run `SELECT id FROM lake.analytics.events WHERE id >= 10 LIMIT 10` over its pinned current snapshot, through CLI and the wire protocol. `information_schema.tables/columns` and `pg_catalog.pg_class/pg_attribute/pg_type` describe that same registered table, field identities and types through the slice 10 provider, without exposing locations or credentials. Example names are synthetic. Registration here is local configuration, never a REST create-table operation; new SQL registration syntax is not required.

**Dependency gates.** Reuse `nata-objstore` for identity-pinned, bounded metadata/data reads, footer handoff/cache and parked I/O bridge; Tokio fetches, CPU workers decode, and ADR 0009 grants precede allocation. [Slice 11's current results](../../bench/results/20261108-object-store-slice.md) explicitly leave real-store timings, RSS/FD, combined bridge model, prepared-plan/auth-scope stress and closing deep checks open. Integration can proceed behind those seams, but slice 12 cannot certify them by inheritance or close until its required upstream gates pass. Slice 10's provider/OID/generation contract must be available; a plain file list loses Iceberg field IDs, pruning and snapshot semantics, so coordinate a typed scan descriptor with its owner rather than flattening that information away. No dependency on new aggregate/join/window features for the thin scan goal; unsupported benchmark SQL is blocked, never replaced silently.

### Read contract

- **Versions:** v2 table metadata and v2 manifest lists/manifests, Parquet data files only. Reject v1 and v3 table metadata and unsupported manifest layouts explicitly, including v1 manifests retained by an upgraded v2 table. Supporting that upgrade case requires a later accepted extension; never interpret missing v1 fields as v2 defaults. Unknown mandatory features/content/codecs fail. v3 deletion vectors/row lineage are out.
- **Snapshots:** load current once per statement; no current snapshot is a valid empty table only when metadata consistently describes that state. A referenced-but-missing snapshot/list is corruption. Pin table UUID, metadata identity, snapshot ID, schema and spec IDs through execution/portal suspension. Concurrent append/refresh affects the next statement only. Prepared execution refreshes/revalidates before rows and errors/reprepares on incompatible shape. Time travel by ID/timestamp, branches/tags and transaction-wide snapshots are **out** and return explicit unsupported errors.
- **Delete files:** position and equality application are **out**. Preflight every delete manifest in the selected snapshot, without partition/stats pruning, and fail `not supported yet: Iceberg position deletes` or `... equality deletes` if any live (ADDED/EXISTING) delete entry exists, even if it seems irrelevant to the predicate. DELETED entries alone need not fail. Do not trust manifest summary counts as proof of absence; unknown content or inconclusive/failed preflight is an error. This gate precedes data-task publication, rows, COUNT shortcuts and LIMIT 0. A mutant skipping it must resurrect rows and fail the fixture. This conservative subset avoids claiming the spike's whole-file delete implementation is bounded production code.
- **Decode/prune:** productionize ADR 0005's selected compact decoder, not its generic Avro tree. Resolve writer schemas and data columns by field ID; validate manifest-list content, spec/schema associations, entry statuses and sequence inheritance. Cross-check decoded added/existing/deleted entry counts against available list counts and reject truncation/inconsistency. Bound Avro schema recursion, varints, block/item counts, strings, maps, decompressed output and codec work before allocation/loops. Support null/deflate/snappy/zstandard only after codec checks pass; no checksum claim for plain Avro. Preserve transport integrity checks; counts cannot detect every valid-byte corruption.
- **Pruning:** inclusive manifest summaries, partition tuples and column bounds/null/NaN counts, with residual SQL filtering always retained. Identity, bucket, truncate, year/month/day/hour and void over their supported primitive source types are checked against spec vectors. Unknown transforms or unavailable/unsafe metrics keep candidates; unsupported partition *values* must be represented losslessly or rejected, never coerced to NULL as in the decoder spike. Interpret each manifest by its own spec ID; mixed-spec tables may conservatively disable partition pruning, retaining column-stat pruning. No optimization requirement for partition evolution. Retain ADR 0005's signed-zero, NaN and truncate-overflow safeguards.
- **Schema evolution:** supported flat scalar SQL types only, with an explicit Iceberg-to-Nata mapping frozen by the reference fixtures. Rename/reorder/drop/add optional columns by ID; absent optional historical fields yield NULL, dropped/re-added names never reuse old IDs. Only Iceberg-safe promotions that Nata represents exactly (int→long, float→double, decimal precision widening at unchanged scale) are accepted; incompatible changes, missing/duplicate/ambiguous Parquet IDs, required absent fields, non-null defaults not implemented by the reader, and nested/new types fail clearly before rows. No name fallback or arbitrary Arrow cast. Unsupported types anywhere in the table schema fail load rather than presenting a misleading partial schema.
- **REST/auth:** GET config (warehouse and defaults/client/overrides precedence per REST contract), namespace existence/listing and table listing/load, including bounded pagination and identifier/path escaping. No remote mutation except OAuth token acquisition. Client-credentials OAuth2 with explicit trusted token endpoint/scope and externally supplied bearer tokens; secrets from private environment/file configuration, never SQL/argv. Cache tokens only in memory by opaque auth scope; refresh expired client tokens with bounded shared work, at most one refresh after 401 within the same request budget; supplied bearer expiry/401 fails for owner rotation. Reject incomplete credentials and 403 directly. TLS with certificate verification for real endpoints; HTTP only explicit loopback test mode. Never follow redirects or catalog-supplied auth endpoint/config outside the locally approved origin policy; REST Authorization never reaches object storage. Ignore no required vended-credential request silently: vended credentials are unsupported; use separately configured slice 11 read identities. Local trust wire mode remains ADR 0013's boundary, not per-user REST authorization.
- **Cache:** authenticated table-load/revalidation each statement; no TTL-only current-pointer cache or cached auth success/failure. Cache immutable table metadata, lists and manifests by catalog identity, table UUID, metadata/snapshot/schema/spec interpretation, immutable object version/validator and opaque credential scope. Validate unversioned objects through slice 11; no trustworthy identity means no cross-query reuse. Generation publication is atomic; load/refresh failure is an error, never empty catalog or stale success. Existing portals retain pins; new statements see new generations. Byte/entry/retained-pin accounting and cancellation follow ADR 0012; one shared node allowance, not an additional uncharged Iceberg cache. Start with duplicate bounded fills rather than new single-flight concurrency unless justified and model-checked.

**Not in scope:** writes/commit/retry protocols, create/drop namespaces or tables remotely, maintenance/manifest rewrite/GC, conditional PUT certification, v1/v3, delete application, time travel/branches/tags, nested types/name mapping, non-Parquet files, metadata SQL tables, optimized partition evolution, vended credentials, Glue/Hive/Nessie, persistent catalogs/OIDs, data/result caches, distributed task retry, new wire TLS/RBAC, new cloud services. Outside scope fails clearly; do not silently read a subset.

## 3. Decision rule (fixed before measuring)

1. **Safety first:** a wrong row, unsound prune, mixed snapshot, secret leak, unbounded allocation/loop or missed cancel blocks the slice. No fallback to directory scanning, ignoring deletes, stale metadata or name matching. Freeze the supported type/transform/codec matrix and all error rules before implementation.
2. **Reuse boundary:** preserve ADR 0005's own compact decoder decision; fill its documented gaps and use independent decoders as oracles. Do not reopen that choice based on historical timing alone. REST reuse vs a small Nata wrapper is open (dependency options below); choose only an option meeting every safety/interop gate. If both qualify, prefer the smaller incremental dependency/unsafe footprint; propose wider reuse only for ≥1.2x planning gain outside paired noise on both CPUs with no cell >1.05x slower and no bounds regression. Missing bake-off is unresolved, never permission to rewrite.
3. **Freeze fairly:** owner/orchestrator records reference values, twin noise, resource envelope, exact workload/version matrix and final per-cell budgets/defaults in `bench/results/YYYYMMDD-iceberg-rest-reference.md`, then freezes this card before production Nata timings. If proposals prove infeasible, seek an explicit prospective amendment then; later misses remain NOT MET. Optional pruning/cache optimization is enabled only if correctness/bounds pass and gain exceeds noise; otherwise keep conservative scan/cache-off control and report the missed target.
4. **Dependency rule:** crates already in root `Cargo.lock` may become direct dependencies **at their locked versions**, with `cargo deny` passing and unsafe inventory recorded. This checkout locks `reqwest` 0.13.5, `serde_json` 1.0.154 and `object_store` 0.14.2; reuse bounded transport/provider seams rather than duplicate TLS/signing. New packages, including new transitives from changed features, mean **stop and report before adding**. Spike lockfiles are not root authorization.

Dependency options (open, no package added by this card):

- Preferred candidate: small Nata-owned REST/OAuth orchestration over locked HTTP/JSON crates, compact decoder using locked compression primitives after feature/lock audit. Cost: own bounded REST/config/pagination/token lifecycle tests; no new runtime or generic manifest tree.
- `iceberg-rust` (`iceberg`, spike used 0.11) for REST/model reuse, or a separate REST-catalog companion crate: **not root-locked**; version/features and complete incremental package count, build size/time, unsafe and license/security weight must be inventoried in the baseline proposal. The historical [decoder bake-off](../../bench/results/20261105-manifest-decode.md) tested decoding, not its REST client; it neither proves REST superiority nor authorizes adding it. Avoid dragging in another object-store/TLS/runtime stack. No fabricated dependency-count estimate.
- `apache-avro` (spike used 0.21) as test-only oracle is also **not root-locked** and requires the same approval/inventory; keep it in the isolated spike/reference environment until approved. DuckDB/PyIceberg external reference environments are pinned tooling, not production Rust dependencies. A new OAuth crate is likewise an explicit dependency proposal; owning cryptography is not an alternative.

**Open questions for the orchestrator before acceptance:** accept the conservative delete/v1/time-travel refusals (including upgraded v2 tables with v1 manifests); select/provision Polaris or the alternative container and approve its private origin/credential configuration; settle the exact scalar mapping and typed slice 10 scan-descriptor ownership; choose dependency option and authorize any new oracle/reuse packages after inventory; sequence remaining slice 10/11 gates and approve reference/heavy-run budgets. None is decided by this draft.

**Stop and report:** scope/default/threshold/dependency changes, a failed safety gate, unavailable provider/grant seam, missing real reference arm, or exhausted time/run budget stop the affected step for the owner/orchestrator. Report rule verbatim, measurements (or NOT MEASURED), verdict and reproduce command plus smallest proposed next step. No automatic alternative, unbounded retry, new cloud service or extra engineering/cloud rerun. A timeout/build failure is INVALID, never a caught mutant. This draft authorizes no implementation, tests or cloud spend.

## 4. Baseline spike (required)

**Question:** can bounded REST/auth plus compact manifest/list decoding satisfy the v2 subset and provider contract, and what are achievable planning/scan/resource baselines? Existing [planning spike](../../spikes/iceberg-plan/README.md), [decoder spike](../../spikes/manifest-decode/README.md) and [commit spike](../../spikes/iceberg-commit/README.md) supply fixtures/ideas, not drop-in production code. The latter's read-only config/load/OAuth code has one-shot tokens and unrestricted body/error formatting; do not copy those behaviors or run its writer suite.

**Smallest experiment/control:** a deterministic loopback REST fake patterned after `nata-objfake`, serving config/namespaces/table loads/token responses and immutable fixture manifests. Script page loops, auth expiry, large/slow/truncated bodies, redirects, snapshot races and per-request trace/counters. Separate data endpoint exercises slice 11. Use pruned/unpruned full-row oracle, compact/generic independent decode controls, cache on/off, and locked-client wrapper vs authorized reuse candidate only if approved. Produce fixtures with PyIceberg and Java Iceberg, including all supported partition values, field renames and rejected delete/v1/v3 cases. No product planner may inherit the spike's unsupported partition-value-as-NULL shortcut or eager task vectors.

**References:** DuckDB's iceberg extension is primary for SQL results and matched end-to-end speed because it exercises SQL filtering and scan execution; PyIceberg is the independent metadata/schema/snapshot/file-task reader, not a speed denominator for SQL. Pin actual versions/extension provenance during the run rather than asserting the spike's versions are current. [Known interop hazards](../../bench/results/20261104-iceberg-plan.md) mean NULL/NaN/signed-zero/truncate cases also compare against fixture rows with pruning disabled; a reference losing rows cannot bless Nata losing them. PyIceberg's historical equality-delete limitation is recorded, while Nata's rejection is checked directly. Speed cells use only the common supported SQL subset; unsupported reference cells block or require prospective scope resolution, never a quiet skip.

**Real catalog:** propose owner-provisioned local Apache Polaris on each reference VM (a pinned local Iceberg REST container is an alternative needing owner selection). Owner supplies approved image/version/runtime, loopback endpoint and token endpoint/origin policy, private read-only client/bearer credentials and warehouse/namespace/table registration, seeded v2 fixtures/Java-written manifests, and readable local or existing object-store locations/identities for both engines. Fixture setup may write only in the separately authorized harness; Nata's identity is read-only. Polaris's prior in-memory/local-disk test mode is not production certification. No new cloud service/metastore/bucket without the owner's approval; absent real catalog/auth/data access means BLOCKED/NOT MEASURED, not fake-as-real PASS.

**Time/spend:** baseline design time box one child turn (about 45 minutes) to prepare the small harness and unresolved-decision report; measurement is separately scheduled, one approved run per architecture and zero unapproved retries. Before each cloud run: same job local small-data/one-round trial plus `scripts/gcp/test/test-job-chains.sh`, then owner-approved current-price estimate (machine/region/Spot/runtime/disk/egress/cleanup). No spend estimate or cloud run made in this doc task. Reference/timing clean VMs: c3d-highcpu-8 and n4a-highcpu-8 Spot. Heavy nightly fuzz, mutants, bound-3 loom and sanitizers use `orchestrate.sh` heavy jobs on 16/32-vCPU Spot sized to work; they never run on the dev VM. Existing `icebergplan`/`icebergplan-mut` jobs provide planning-fixture precedents; `iceberg`, `icebergspikes`, `icebergpolaris`, `icebergcs` and `icebergmodel` run commit/write/model work and are **not** this slice's read-only acceptance jobs. Add a narrow read-only heavy step file rather than invoking them wholesale.

### Step plan (one bounded child turn per step)

Each implementation brief names paths, gates and one roughly 45-minute deliverable; if it cannot finish, stop with a concrete continuation. No child owns an indefinite multi-step round. Heavy runs and approval waits are separate owner/orchestrator actions.

6. Complete sound pruning, field-ID schema evolution/promotions and conservative mixed-spec behavior, differential/property suite and delete-preflight bypass mutants in the same change.

12. Prepare/trigger authorized deep/nightly checks **on the closing commit**, then hand back while jobs run: full new and existing touched-path fuzzers, loom bound 3, full SQL subset fuzzer, mutant sweeps and relevant sanitizer/Miri checks, on separately sized heavy infrastructure.

14. Closeout only after all required results exist: results/ADR/register/regression/supported-SQL/config docs and throwaway-spike cleanup. Never delete shared spikes still needed by write work without owner coordination.
