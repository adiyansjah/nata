## 1. Goal

Default psql, pgjdbc (including DBeaver's use of it), psycopg, pgcli and ADBC PostgreSQL can connect, discover registered schemas/tables/columns, run supported read-only SQL, stream, cancel and recover. Catalog answers, `SHOW` and `DESCRIBE` come from one typed Nata catalog snapshot, never from invented PostgreSQL objects. Example: `SHOW TABLES FROM public`, `DESCRIBE public.example`, `psql \dt public.*` and `psql \d public.example` agree about the same registered table.

**Already delivered, not new scope:** read the dated amendments of ADR 0008 and [serve.md](../serve.md), not just card 0003's original scope. Simple and named/unnamed extended queries, default preparation and scalar binary parameters/results, binary numeric results, a bounded binary COPY SELECT adapter, cancel and send deadlines already exist. The two reopenings are documented in [fixes](../../bench/results/20261107-pgwire-fixes.md) and [second fixes](../../bench/results/20261107-pgwire-fixes2.md): configured clients and a bootstrap-only catalog did not establish default-client compatibility. DATE output R19 is subsequently closed by [Debt A](../../bench/results/20261107-debt-a.md); no four-digit-only regression is allowed.

| Remaining protocol choice | Proposed scope and reason (reasoned unless linked above) |
|---|---|
| SSL/TLS negotiation | Preserve correct SSLRequest/GSS refusal; no encryption advertisement or silent downgrade after accepting SSL. TLS is T1 in feature map A/I, deferred to the secure-server slice; ADR 0013 states its acceptance conditions. Default clients must still connect in their default prefer mode; explicit require/verify must fail honestly. |
| Beyond trust: password/SCRAM | Deferred with TLS to T1; no cleartext-password or MD5 implementation and no authentication claim. Loopback trust and the existing explicit unsafe-listen warning remain. User/database remain routing labels, not identities. |
| Execute max-rows / PortalSuspended | Taken in: positive fetch sizes, incremental exact rows, no collect-all/re-execution. ADR 0015 bounds retained admissions, workers, bytes and idle lifetime; expired portals fail explicitly. This addresses the documented JDBC fetch refusal, not object-store pagination. |
| Named SQL cursors (`DECLARE/FETCH`) | Deferred to an explicit read-only cursor/transaction slice: wire portals do not imply SQL cursors, scrollability, WITH HOLD or transaction snapshots. Return positioned 0A000; exercise default psycopg normally and separately test ServerCursor refusal. Owner must accept this compatibility boundary. |
| COPY forms used by clients | Keep default ADBC binary `COPY (SELECT …) TO STDOUT`, now wrapping any already-supported read-only SELECT, and add query TO STDOUT text/CSV and registered-table TO STDOUT shorthand for psql/JDBC export APIs. Freeze exact option spellings from part 4. PostgreSQL text/CSV quoting, escaping, NULL/empty distinctions and headers are the oracle. COPY FROM, server files, PROGRAM, object-store export and writes remain 0A000. No new general SQL operators to make a COPY query work. |
| Binary result format | Already delivered: retain mixed per-column formats and exact OIDs/typmods, text/binary/COPY parity, all existing scalar domains. Binary numeric input remains explicitly unsupported; no new data types or parameter inference promises. New track-A result types need a separately frozen mapping before serving them. |
| statement_timeout / cancel under load | Take nonzero statement_timeout in milliseconds with documented unit syntax; shared cancel path covers admission, planning, execution, output and suspended portals. Preserve reserved cancel sockets, wrong/stale-key isolation, partial-frame close and Sync recovery. ADR 0015 defines deadline scope. |

**Catalog contract:** ADR 0014 supplies the minimum relation/column inventory and semantic rules. Its captured-client additions must be frozen before implementation: psql describe/list, JDBC DatabaseMetaData, DBeaver's PostgreSQL driver metadata and pgcli completion queries must actually execute. This replaces the two exact ADBC bootstrap responses in `crates/nata-pgwire/src/session.rs`; passing only those two is insufficient. Empty catalogs, quoted/mixed-case names, duplicate names across schemas, NULLability, exact decimal precision/scale, exceptional dates and unsupported types are fixtures. Truly absent indexes/constraints/functions may return typed empty relations; an unsupported catalog object/query returns 0A000, never an empty answer pretending absence.

**SHOW / DESCRIBE:** include `SHOW CATALOGS`, `SHOW SCHEMAS [FROM catalog]`, `SHOW TABLES [FROM [catalog.]schema]`, `SHOW COLUMNS FROM table` and `DESCRIBE table`. Proposed output contracts: catalogs(catalog_name); schemas(catalog_name,schema_name); tables(table_catalog,table_schema,table_name,table_type); columns/DESCRIBE(column_name,data_type,is_nullable,ordinal_position,numeric_precision,numeric_scale). Same ordering and values as catalog views, with positioned errors on ambiguity/missing objects. Publish examples in supported-SQL/serve docs at implementation closeout.

**SET / SHOW:** retain the serve allowlist and honest refusals; add effective `search_path` for registered names, `current_schemas`, `SHOW ALL`, `RESET name/ALL`, `current_setting(name[, missing_ok])` and pg_settings from that same registry. Formatting settings retain their documented restricted domains; TimeZone still has no effect on Date32. Nonzero statement_timeout is enforced, not a stored no-op. No SET LOCAL, arbitrary startup options, role changes or isolation/rollback guarantees. Compatibility BEGIN/COMMIT/ROLLBACK retain I/T/E markers, with failed-transaction recovery tested. ADR 0015 specifies read-only reporting without turning this into a write slice.

**Parallel seam / exclusions:** use the current in-memory registered-catalog interface, with an immutable fixture-backed provider until track B's real provider exists; metadata never walks directories or invents tables for file paths. Track B owns catalog registration/storage and CREATE/DROP CATALOG (B6/H T0); this card reads its snapshots, never mutates them. Parent must name that interface and owner before implementation. Metadata SQL support must work without waiting for track A joins/sorts: reuse the current parser and lower only the frozen metadata-query corpus onto bounded typed metadata operations, not another general SQL engine or raw SQL string canned answers. Ordinary user SQL continues through nata-sql; each newly merged A slice supplies wire regression queries. A required query outside the bounded metadata surface stops for parent scope resolution. Interactive CLI/REPL, Flight SQL (T1), general PostgreSQL emulation, writes, cloud work and edits to accepted ADRs/other cards are outside this planning task.

## 3. Decision rules (fixed before measuring)

**Partial freeze, 2026-11-07** (`bench/results/20261107-wire-catalog-reference.md`): streaming ≤1.10x PostgreSQL with the same client is frozen for psycopg and ADBC (valid medians on both CPU types); schema browsing ≤1.20x PostgreSQL with the same client is frozen. The psql, Rust raw-protocol and JVM cells were re-measured with the corrected harness (run `wcap-*-1107-r3`, in the same record), so streaming ≤1.10x PostgreSQL is now frozen for all six clients on both CPU types. PostgreSQL 15/16 differences and a real DBeaver UI capture are also still open.

- Semantics, isolation, bounds and default-client browsing are gates. Zero unexplained mismatches, hangs or surviving required mutants (targets); INVALID does not count as a catch. Supported metadata queries must operate on catalog rows, not recognize exact SQL and return canned values. No blanket exception for tools' SQL.
- Freeze client versions/actions, captured SQL, column/function inventory, PostgreSQL compatibility version and projection differences after part 4, before implementation. Capture PostgreSQL corresponding to the advertised compatibility version; if using a different version, compare both or record the mismatch as unresolved. PostgreSQL OIDs are compared through a declared identity mapping for Nata objects, not raw generated numbers. Built-in type IDs and wire bytes remain exact.
- P16's ≤1.10x is a **provisional target** based on existing matched-client evidence, not a measured attainable bound. Re-run PostgreSQL first for every arm and CPU; owner/parent freezes the target and RSS/browse budgets in this draft with the result link before timing Nata. No automatic relaxation when the reference is noisy: unresolved cells stop the freeze. Once frozen, every missed arm stays a miss; no averaging CPUs/clients/formats to pass. Small-query controls retain the target ≤1.20x paired regression gate and a planted slowdown must fail it.
- Use same fixture/order/types/bytes, connection lifetime, startup inclusion, cache, client decode/sink and hardware per arm. Report engine/source time separately: PostgreSQL table scans versus Parquet are an end-to-end protocol reference, not proof of pure codec cost. Performance changes require correct outputs and a gain beyond twin noise on both CPUs; retain bounds even if a faster unbounded variant wins.
- Keep existing hand codec/runtime. No speculative pgwire reuse bake-off: ADR 0008 requires a released decoder fix and full R1 replay before reconsideration. No new dependencies approved here. Parent implementation brief must name direct dependencies at locked versions, deny/unsafe inventory obligations; an unlocked crate stops for approval.
- Owner must accept T1 security deferral, SQL-cursor boundary, COPY expansion and bounded portal tradeoff. If these cannot fit a small complete slice, return a proposed split before implementation; do not merge stubs, silently omit a client or change accepted ADRs.
- **RSS and browse budget, frozen by the parent on 2026-11-08, before any loaded Nata measurement** (the closeout child stopped at
  item 3 because no budget was frozen). The budget is derived from the caps this card already sets, not from a measurement:
  for the loaded browse/streaming workload with S concurrent sessions, Nata's peak RSS (cgroup `memory.peak`, or `VmHWM` when no
  cgroup) must stay within **idle RSS + S × (16 MiB snapshot cap + 512 KiB wire buffers) + the engine query budget configured for the
  run + 64 MiB fixed allowance**, and must return to within **idle RSS + 64 MiB** within 10 s after every session closes. FDs return
  to the idle count after close. Each term is printed by the gate; any excess is a FAIL, never a re-derived budget. A mutant that
  removes the snapshot cap must exceed it. PostgreSQL's RSS for the same workload is recorded beside it as context only.
- **P16 freeze procedure (unchanged rule, made runnable):** the heavy job runs the PostgreSQL arms first on each CPU, writes their
  medians and twin noise, and only then runs the Nata arms; the ≤1.10x per-client target is judged against those PostgreSQL arms
  from the same VM. An unresolved PostgreSQL cell (twin noise over 5%) marks that cell UNRESOLVED, never MET.
